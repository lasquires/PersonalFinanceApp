# Keyless SNAP intake

Muse's scheduled worker cannot access its Vault token. Add a separate, unauthenticated POST endpoint for a SNAP balance observation, without weakening the existing token-authenticated route. The public endpoint is not a source of truth: any internet client can submit plausible data. Show accepted observations on the signed-in dashboard as **Unverified report**, with the observation time and a stale warning after 36 hours. Never merge public observations into the trusted SNAP snapshot table or financial review exports.

Accept only strict JSON containing `benefit_month` (`YYYY-MM`, current or previous Eastern calendar month), `balance_cents` (integer 0-250000), and `observed_at` (ISO date-time within 10 minutes of server time). Limit bodies to 4 KiB. Use the Vercel-provided client IP and a database-atomic 10/minute and 100/hour rate limit. Store only a hash of the IP. Keep one latest accepted and one latest flagged observation per benefit month. Flag increases above $500 compared with the latest same-month accepted or trusted observation; flagged readings must not replace the displayed amount. Older observations must not replace newer ones. Return the same `{ "ok": true }` receipt for accepted, repeated, and flagged valid observations so an anonymous caller cannot probe stored balances.

If the newest accepted observation is newer than the newest trusted one, show it with its unverified label. Keep the trusted read visible where relevant, and warn if a flagged reading needs checking. The dashboard must not imply Muse has run when there is no report. A successful submission does not prove the ConnectEBT read happened; Muse must send only balances it actually read and must report read failures instead of fabricating a timestamp.

Document the exact scheduled Muse job and its remaining dependencies: authenticated ConnectEBT access and a working Muse scheduler. Do not ask the user to share benefit-site credentials with this app or ChatGPT.
